# 接口契约

> **模块1已确认，本版本为最终版接口规范，请所有模块对齐。**

## 通用约定

### 1. 接口前缀

全部接口统一前缀：`/api/v1/`

### 2. 统一响应外层包装

**所有接口返回统一使用以下外层包装，HTTP 状态码固定为 200，业务错误通过 `code` 字段区分：**

```json
{
    "code": 0,
    "msg": "success",
    "data": { }
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| code | int | 业务状态码，`0` 表示成功，非 `0` 表示业务错误 |
| msg | string | 状态描述，成功为 "success"，错误为具体错误信息 |
| data | object/array/null | 业务数据，成功时为具体数据，错误时为 `null` |

### 3. 业务错误码约定

| code | 含义 |
|------|------|
| 0 | 成功 |
| 1001 | 参数错误 / 缺少必填字段 |
| 1002 | 图片质量不合格（不调用模型推理，直接返回） |
| 1003 | 诊断记录不存在 |
| 5000 | 服务器内部错误 |

错误响应示例：

```json
{
    "code": 1002,
    "msg": "图片模糊，无法识别",
    "data": null
}
```

### 4. 模块职责划分

- **5号（后端）**：负责所有 `/api/v1/*` 接口的实现，对模型、知识库、数据库做适配封装
- **4号（模型）、7号（知识库）、8号（数据库）**：模块内部函数签名保持不变，由后端统一调用适配
- **6号（前端）**：按照本文档 JSON 样例进行 Mock 开发

## 1. 病害诊断接口

**请求地址：** POST /api/v1/diagnoses
**请求格式：** multipart/form-data

### 请求字段

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| image | file | 是 | 用户上传的小麦图片 |
| region | string | 是 | 地区（如"陕西省西安市"） |
| growth_stage | string | 是 | 小麦生育期（如"拔节期"、"抽穗期"） |
| field | string | 否 | 地块名称（用于标识具体田块） |

### 成功响应（code=0）

```json
{

    "msg": "success",
    "data": {

        "created_at": "2026-08-15T10:30:08+08:00",
        "image_quality": {
            "passed": true,
            "code": "OK",
            "message": "图片质量合格"
        },
        "predictions": [
            {"class_id": 13, "class_name": "Yellow Rust", "display_name": "小麦条锈病", "confidence": 0.91},
            {"class_id": 3, "class_name": "Brown Rust", "display_name": "小麦叶锈病", "confidence": 0.06},
            {"class_id": 10, "class_name": "Septoria", "display_name": "壳针孢叶斑病", "confidence": 0.03}
        ],
        "reliable": true,
        "threshold": 0.75,
        "knowledge": {
            "introduction": "病害介绍",

            "daily": []
        }
    }
}
```

### 图片质检失败响应（code=1002）

> **重要：质检失败时不调用模型推理，直接返回错误。**

```json
{
    "code": 1002,
    "msg": "图片模糊，无法识别",
    "data": {
        "image_quality": {
            "passed": false,
            "code": "BLURRY",
            "message": "图片模糊，无法识别"
        }
    }
}
```

### image_quality 字段说明

统一使用**对象结构**，不再使用布尔值：

| 字段 | 类型 | 说明 |
|------|------|------|
| passed | boolean | 图片质量是否合格（true=合格，false=不合格） |
| code | string | 状态码：`OK` / `BLURRY`（模糊）/ `TOO_DARK`（过暗）/ `NO_WHEAT`（未检测到小麦） |
| message | string | 图片质量检测的具体描述 |

### 字段责任约定

#### class_id（类别编号）

- **最终来源：** 由模型（3号 ResNet50 / 4号 ConvNeXt）输出，模型推理返回的类别索引即为 `class_id`。
- **Mock阶段约定：** 4号交付模型前，由5号（后端）临时生成 Mock ID 占位，但必须遵循以下规则：
  1. 5号需与4号确认模型的类别顺序，Mock ID 尽量与最终模型输出的索引对齐。
  2. 4号交付模型时，必须同时提供「类别映射表」（class_id → 英文类别名），5号据此替换 Mock 逻辑。
  3. 类别映射表统一放在 `docs/类别映射表.md`，由4号维护。

#### display_name（中文名称）

- **责任方：7号（知识库）** 负责维护并返回中文名称。
- 7号的知识库必须包含 `class_id → 中文名称` 的完整映射（15类病虫害），后端调用知识库获取 `display_name`。
- 5号（后端）不在适配层做中英文硬编码映射，所有中文名称以知识库返回为准。

## 3. 长势评估接口（新增）

**说明：** 基于专家规则引擎+加权评分法的小麦长势综合评估，输入环境、土壤、农事等数据，输出长势评分、等级、短板分析和针对性干预建议。与病虫害识别功能互补，构成完整的田间智能辅助决策能力。

### 3.1 提交长势评估

**请求地址：** POST /api/v1/growth/evaluate
**请求格式：** multipart/form-data

#### 请求字段

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| growth_stage | string | 是 | 生育期：tillering(分蘖期)/reviving(返青期)/jointing(拔节期)/heading(抽穗期)/filling(灌浆期) |
| temperature | float | 是 | 日均温(℃) |
| soil_moisture | float | 是 | 土壤湿度(%田间持水量) |
| soil_fertility | float | 是 | 土壤肥力指数(0-100) |
| sunlight | float | 是 | 光照时长(小时/天) |
| farming_operation | float | 否 | 农事操作完成度(0-100)，默认70 |
| pest_risk | float | 否 | 病虫害风险指数(0-100，越低越好)，默认20 |
| visual_condition | float | 否 | 视觉苗情评分(0-100)，可选（可复用图像识别结果） |
| region | string | 否 | 地区 |
| field | string | 否 | 地块名称 |

### 模块职责

- **7号（知识库）**：负责维护各生育期的评分规则（`knowledge/growth_rules/growth_stages.json`）和干预建议库（`intervention_suggestions.json`）
- **8号（数据库/天气）**：提供天气、土壤数据查询接口，可对接长势评估的趋势预判
- **5号（后端）**：实现评分计算逻辑，封装为 `/api/v1/growth/*` 接口
- **6号（前端）**：新增长势评估页面，用户填写参数后展示评分、等级、短板分析和操作建议
