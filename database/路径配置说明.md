# 路径配置说明（2 号交付物）

> **用途**：当其他成员在本地下载本项目代码并准备使用数据集时，按本文档配置数据路径即可直接运行所有脚本，无需修改代码。

---

## 1. 项目根约定

本项目以 `wheat-disease-monitor/` 为**项目根目录**（即 git 仓库根）。

所有代码文件通过 `Path(__file__).resolve().parent` 自动推导路径，**不写死任何绝对路径**，整个项目文件夹搬到任意盘符 / 任意目录均可直接运行。

---

## 2. 标准目录结构

克隆仓库后，在项目根下创建 `data/` 目录，把数据集放进去：

│   ├── data_processing_report.md          数据处理报告

## 3. 快速配置（3 步）

### 步骤 1：克隆仓库

```bash
git clone https://gitee.com/zywddywz/wheat-disease-monitor.git
cd wheat-disease-monitor
```

### 步骤 2：创建 data 目录并放入数据集

```bash
# 在项目根下创建 data 目录
mkdir data

# 把「合并数据集」文件夹放到 data/ 下
# 最终结构应为：wheat-disease-monitor/data/合并数据集/train/Aphid/xxx.jpg
```

> **数据集来源**：从 2 号（数据处理）处获取 `合并数据集.zip`，解压后整个文件夹放到 `data/` 下即可。

### 步骤 3：直接运行脚本（无需改任何路径）

```bash
# 离线增强（自动找到 data/合并数据集/train/）
python database/augment_offline_few_shot.py

# 类别映射升级
python upgrade_class_mapping.py

# 重新生成交付物
python build_delivery.py
```

所有脚本会自动通过 `Path(__file__)` 推导出 `data/合并数据集/` 的位置，无需传参。

## 4. 各脚本的路径推导逻辑

| 脚本 | 所在位置 | 推导方式 | 默认数据目录 |
|---|---|---|---|
| `augment_offline_few_shot.py` | `database/` | `__file__` → 上 1 级 → `data/合并数据集/` | `../data/合并数据集/` |
| `upgrade_class_mapping.py` | 项目根 | `__file__` → 同级 → `data/合并数据集/` | `./data/合并数据集/` |
| `build_delivery.py` | 项目根 | `__file__` → 同级 → `data/合并数据集/` | `./data/合并数据集/` |
| `merge_datasets.py` | `database/` | 命令行参数 `--sources` `--output` | 无默认（必传参数） |

### Python 代码示例（路径推导原理）

```python
from pathlib import Path

# 以 augment_offline_few_shot.py 为例（位于 database/ 下）
script_dir = Path(__file__).resolve().parent    # wheat-disease-monitor/database/
project_root = script_dir.parent                 # wheat-disease-monitor/
data_dir = project_root / 'data' / '合并数据集'   # wheat-disease-monitor/data/合并数据集/
```

## 5. 如果数据集不在默认位置（自定义路径）

如果你的数据集不在 `wheat-disease-monitor/data/合并数据集/`，有两种方式处理：

### 方式 A：命令行参数覆盖（推荐，不改代码）

```bash
# 离线增强 —— 指定数据集根目录
python database/augment_offline_few_shot.py --dataset_root "D:/my_data/合并数据集"

# 数据集合并 —— 指定源和输出
python database/merge_datasets.py \
    --sources "数据集1=./data/数据集1" "archive=./data/archive" \
    --output "./data/合并数据集"
```

### 方式 B：创建软链接（不改代码，不传参数）

```bash
# Windows（管理员权限 CMD）
mklink /D "wheat-disease-monitor\data\合并数据集" "D:\my_data\合并数据集"

# Linux / macOS
ln -s /home/user/my_data/合并数据集 wheat-disease-monitor/data/合并数据集
```

### 方式 C：直接放默认位置（最省事）

把数据集文件夹放到 `wheat-disease-monitor/data/合并数据集/` 下即可，所有脚本零配置直接运行。

## 6. 数据集合并脚本（merge_datasets.py）专项说明

`merge_datasets.py` 用于从两个原始数据源重新合并生成标准数据集，需要通过命令行参数指定源路径：

```bash
python database/merge_datasets.py \
    --sources "数据集1=./data/数据集1" "archive=./data/archive" \
    --output "./data/合并数据集"
```

| 参数 | 说明 | 示例 |
|---|---|---|
| `--sources` | 数据源列表，格式 `名称=相对路径`，至少 2 个 | `"数据集1=./data/数据集1" "archive=./data/archive"` |
| `--output` | 合并输出根目录 | `./data/合并数据集` |

> **注意**：`数据集1` 和 `archive` 这两个名称是固定的（代码内部用这两个 key 匹配命名规则），不能改成其他名字。

## 8. 常见问题

### Q1：运行脚本报 `DirectoryNotFoundError: 找不到 data/合并数据集/`

**原因**：数据集未放到默认位置。

**解决**：
1. 确认 `wheat-disease-monitor/data/合并数据集/train/` 目录存在
2. 或用 `--dataset_root` 参数指定实际位置

### Q2：`merge_datasets.py` 报 `数据源名必须是 数据集1 / archive`

**原因**：`--sources` 参数中的名称写错了。

**解决**：必须用 `数据集1` 和 `archive` 这两个固定名称：
```bash
# 正确
--sources "数据集1=./data/数据集1" "archive=./data/archive"
# 错误（名称不对）
--sources "dataset1=./data/数据集1" "archive=./data/archive"
```

### Q3：数据集图片要不要入 git？

**不要**。`data/` 目录已加入 `.gitignore`，35,000+ 张图片不入仓库。仓库内只保留：
- 代码文件（`.py`）
- 元文件（`class_mapping.json`、`processing_report.json`、`manifest.csv`、`manifest_augmented.csv`）
- 文档（`.md`）

### Q4：换了一台电脑，路径全变了怎么办？

**无需任何修改**。所有脚本用 `Path(__file__)` 推导路径，只要项目目录结构不变（`data/合并数据集/` 在项目根下），换电脑 / 换盘符直接运行。

## 9. 路径检查命令

克隆并配置好数据集后，运行以下命令验证路径是否正确：

```bash
# 验证数据集目录是否就位
python -c "from pathlib import Path; p=Path('data/合并数据集/train'); print('OK' if p.is_dir() else 'NOT FOUND:', p)"

# 验证离线增强脚本能找到数据集
python database/augment_offline_few_shot.py --help
```

如果第一条输出 `OK`，说明路径配置完成，可以开始使用所有脚本。
